# Asset Permission Record

## Purpose

This document records the project's permission to reuse material from **WarFighter Modification - Total Overhaul**. It is a project-control record and should be read together with the preserved original permission conversation.

## Recorded permission

- **Source project:** WarFighter Modification - Total Overhaul
- **Permission grantor:** Yuri, identified by the project owner as the primary WarFighter developer
- **Permission recipient:** Gates of WarFighter project owner
- **Recorded by:** Repository owner
- **Record date:** 2026-08-09
- **Permission confirmed:** Express approval to use the complete WarFighter mod and all content included with it for Gates of WarFighter
- **Included content:** Models, textures, materials, normal maps, animations, rigs, sounds, music, voice work, maps, scripts, configuration, localization, UI, logos, branding, and supporting files included with WarFighter
- **Approved use:** Porting, modifying, integrating, and redistributing that content as part of the standalone Gates of WarFighter mod for Call to Arms: Gates of Hell

## Scope

Yuri's approval covers the complete WarFighter content library used by this project. No WarFighter asset category requires a separate project permission gate before technical import.

The project must still preserve provenance and attribution. Permission to use the content does not transfer ownership, erase original authorship, or permit the project to claim that upstream work was created by Gates of WarFighter contributors.

## Evidence record

The original permission conversation should be preserved outside the public repository. A redacted or Yuri-approved copy may be added under `docs/permission-evidence/` when appropriate.

The evidence record should capture:

1. Yuri's account identity or other reliable identifier
2. The date and platform of the conversation
3. The exact permission language
4. Any requested credit wording
5. Any distribution or presentation conditions Yuri specified

Do not publish private messages, personal information, or screenshots without the participants' consent.

## Asset acceptance rule

WarFighter-derived files may enter the project through approved implementation slices. Each manifest entry must record:

- Source path and source version
- Asset type
- Original author or best-known contributor where identifiable
- Permission basis: complete WarFighter approval from Yuri
- Required attribution
- Dependencies
- Conversion steps
- Destination path
- File hash before and after conversion
- Reviewer and acceptance status

The manifest exists to preserve technical provenance, reproducibility, dependency completeness, and credit. It is not an asset-by-asset reauthorization process.

## Dispute handling

If a contributor raises an authorship, credit, or use concern, the affected content should be reviewed promptly and respectfully. The project should preserve the permission record and technical provenance, correct missing attribution, and coordinate with Yuri and the contributor as needed.
